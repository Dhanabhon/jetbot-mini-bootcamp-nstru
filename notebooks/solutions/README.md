# Solutions และ Checkpoint

เฉลยของแต่ละ module ตั้งชื่อไฟล์ให้ตรงกับ notebook ต้นฉบับ เช่น `04_pid_line_following_solution.ipynb`

ไฟล์ `.ipynb` ในโฟลเดอร์นี้สร้างอัตโนมัติจาก `notebooks/src/` ด้วย `python3 tools/build_notebooks.py` อย่าแก้ตรงนี้

ถ้าตามไม่ทันใน module ไหน ให้เปิดเฉลยของ module นั้นแล้วไปต่อ module ถัดไปได้เลย

## แบบสคริปต์: ทำผ่านหน้าเว็บแทน notebook

ทุก module มีสคริปต์ที่ทำงานเหมือนเฉลย แต่ปรับค่าผ่านหน้าเว็บที่มีภาพสดจากกล้อง ไม่ต้องรัน cell ซ้ำทุกครั้งที่ขยับรถ ค่าที่บันทึกลง `my_params.json` เป็นไฟล์เดียวกับที่ notebook ใช้

| สคริปต์ | ทำอะไร |
| :--- | :--- |
| `01_system_check.py` | ดูแบต FPS กล้อง ทดสอบ buzzer จอ OLED และเดินหน้า 1 วินาที |
| `02_trim_tuner.py` | วิ่งตรง วัดว่าเบี้ยวกี่ ซม. แล้วให้โปรแกรมคำนวณ `left_gain` / `right_gain` |
| `03_line_tuner.py` | จูน `roi_top` และ `black_v_max` ดู mask เส้นดำและสีเขียว |
| `04_pid_tuner.py` | ปรับ `Kp`, `Kd` และความเร็วระหว่างรถวิ่ง |
| `05_sign_viewer.py` | ดูการอ่านป้ายพร้อมตัวเลขที่ใช้ตัดสิน และเก็บภาพไว้เทรน |
| `05_sign_cnn.py` | เก็บภาพ เทรน ResNet18 บนรถด้วยปุ่มเดียว แล้วทดสอบอ่านป้ายสด |
| `06_mission_runner.py` | รัน FSM ทั้งภารกิจ เริ่มที่โหมดดูอย่างเดียว (มอเตอร์ไม่หมุน) |
| `07_race_runner.py` | วันแข่ง: แท็บภารกิจ + PID + เส้นดำ บันทึกผลทุกรอบลง `race_log.csv` |
| `jetbot_app.py` (root ของ repo) | ทุกแท็บรวมในโปรแกรมเดียว สำหรับใช้ต่อหลังอบรม (ดูหัวข้อท้ายไฟล์) |

2. เปิด Terminal ใน Jupyter Lab (**File > New > Terminal**) แล้วสั่ง เช่น

   ```bash
   cd ~/jetbot-mini-bootcamp-nstru
   python3 notebooks/solutions/02_trim_tuner.py
   ```

3. เปิด `http://10.42.0.1:8080` ใน Chrome
4. กด `Space` เพื่อหยุดรถได้ทุกเมื่อ จบโปรแกรมด้วย `Ctrl` + `C` ใน Terminal กล้องจะว่างให้ notebook ใช้ต่อ

รถจะหยุดเองเมื่อปิดแท็บ คอมพิวเตอร์หลุดจาก Wi-Fi ของหุ่นยนต์เกิน 1.5 วินาที เปลี่ยนแท็บในหน้าเว็บ หรือปิดแท็บ Terminal ที่รันโปรแกรมอยู่

## Module 1 แบบสคริปต์: ตรวจเครื่อง

`01_system_check.py` แสดงแรงดันแบตเป็นเปอร์เซ็นต์และ FPS ของกล้อง กด **เสียง beep** **แสดงบนจอ** และ **เดินหน้า 1 วินาที** เพื่อตรวจ buzzer จอ OLED และมอเตอร์ ถ้าข้อความบน OLED หายไปเอง ให้สั่ง `sudo systemctl stop nstru_status jetbotmini_stats` ก่อน

## Module 2 แบบสคริปต์: ปรับให้รถวิ่งตรง

`02_trim_tuner.py` ทำแบบเดียวกับ notebook Module 2

1. แปะเทปเส้นตรง 1 เมตร วางรถให้ล้อหน้าอยู่ต้นเส้น ตั้ง **ความเร็วทดสอบ** เป็นความเร็วที่จะใช้แข่ง
2. กด **วิ่งทดสอบ** แล้ววัดว่าปลายทางเบี้ยวออกจากเส้นกี่ ซม. (ขวาเป็นบวก ซ้ายเป็นลบ)
3. ใส่ระยะแล้วกด **ปรับ trim** โปรแกรมลด gain ของล้อที่เร็วกว่า 0.005 ต่อ 1 ซม. วิ่งซ้ำจนเบี้ยวไม่เกิน 2 ซม.
4. กด **บันทึก** ค่าจะถูกใช้ใน Module 4, 6 และ 7

2. เปิด Terminal ใน Jupyter Lab (**File > New > Terminal**) แล้วสั่ง

   ```bash

   python3 notebooks/solutions/03_line_tuner.py
   ```

4. เลื่อน `roi_top` ให้กรอบส้มครอบพื้นถนนหน้ารถ แล้วเลื่อน `black_v_max` จนภาพ mask ด้านล่างเห็นเส้นเต็ม ๆ แต่ไม่มีจุดขาวบนพื้น สลับไปดู **mask สีเขียว** ตอนวางรถหน้าจุดตัดเพื่อตรวจว่าเห็นสี่เหลี่ยมเขียว
5. กด **บันทึกลง my_params.json** ค่าจะถูกใช้ต่อใน Module 4, 6 และ 7 เหมือนบันทึกจาก notebook

## Module 5 แบบสคริปต์: ดูการอ่านป้ายและเก็บภาพไว้เทรน

`05_sign_viewer.py` แสดงภาพกล้องพร้อมกรอบป้ายที่อ่านได้ ป้ายที่ `SignVoter` ยืนยันแล้ว และตัวเลขที่ใช้ตัดสิน ใช้หาสาเหตุเมื่ออ่านป้ายผิด และเก็บภาพไว้เทรน classifier

1. ปิด kernel ของ notebook ทุกตัวก่อน (เมนู **Kernel > Shut Down All Kernels**)
2. เปิด Terminal ใน Jupyter Lab แล้วสั่ง

   ```bash
   cd ~/jetbot-mini-bootcamp-nstru
   python3 notebooks/solutions/05_sign_viewer.py
   ```

3. เปิด `http://10.42.0.1:8080` ใน Chrome แล้วถือป้ายหรือวางรถหน้าเสาป้าย ป้ายต้องอยู่เหนือเส้นขาวแนวนอนบนภาพ
4. แถวบนสุดของภาพบอกว่าทำไมได้ป้ายนั้น เช่น `SIGN LEFT  blue ext 0.79 bal +0.32`

| ค่า | ความหมาย | ถ้าผิด |
| :--- | :--- | :--- |
| `red` | ป้ายสีแดงคือ STOP เสมอ | |
| `ext` | พื้นที่ป้าย / พื้นที่กรอบ ตั้งแต่ 0.90 คือ PARKING ต่ำกว่านั้นคือป้ายลูกศร | PARKING ได้ต่ำกว่า 0.90: ป้ายเอียง หรือ mask น้ำเงินขาดเป็นชิ้น ดูที่ **mask น้ำเงิน** |
| `bal` | สีขาวครึ่งบนของป้าย ฝั่งซ้ายมากกว่าขวาเท่าไร เกิน +0.15 คือ LEFT ต่ำกว่า -0.15 คือ RIGHT | ได้ใกล้ 0 ตลอดจนทุกป้ายเป็น STRAIGHT: ลูกศรมืดหรืออมฟ้าจนไม่นับเป็นสีขาว ดูที่ **mask ขาว** ว่าลูกศรขึ้นเป็นสีขาวไหม |

5. เก็บภาพ: กดปุ่มเลข `1`–`5` บนคีย์บอร์ด (หรือคลิกปุ่ม) ภาพจากกล้องจะถูกเก็บใน `dataset/signs/<ชนิดป้าย>/` ที่เดียวกับ notebook ภาพเหล่านี้ไม่ถูก commit ขึ้น git
6. กลับไปที่ Terminal แล้วกด `Ctrl` + `C` เพื่อหยุด

## Module 5 แบบสคริปต์: เทรน CNN อ่านป้ายบนรถ

`05_sign_cnn.py` เป็นทางเลือก Deep Learning ของ Module 5 ทำครบในหน้าเว็บเดียว ไม่ต้องเปิด notebook: เก็บภาพ เทรน ResNet18 บน GPU ของรถ แล้วถือป้ายหน้ากล้องดูว่า model ทายอะไรและมั่นใจกี่เปอร์เซ็นต์ ภารกิจใน Module 6–7 ยังอ่านป้ายด้วย OpenCV เหมือนเดิม

การเทรนเริ่มจาก weights ของ ResNet18 ที่เทรนกับ ImageNet มาแล้ว ไฟล์ `models/resnet18-f37072fd.pth` (47 MB) มากับ repo เพราะ hotspot ของรถไม่มีอินเทอร์เน็ต รถที่ clone ไว้ก่อนหน้านี้ให้สั่ง `git pull` หนึ่งครั้งตอนรถต่อเน็ตได้ ไฟล์นี้ดาวน์โหลดมาจาก [download.pytorch.org](https://download.pytorch.org/models/resnet18-f37072fd.pth) ตัวเดียวกับที่ torchvision ใช้

1. ปิด kernel ของ notebook ทุกตัวก่อน (กล้องและ GPU ใช้ได้ทีละโปรแกรม) แล้วสั่งใน Terminal ของ Jupyter Lab

   ```bash
   cd ~/jetbot-mini-bootcamp-nstru
   python3 notebooks/solutions/05_sign_cnn.py
   ```

2. เปิด `http://10.42.0.1:8080` ใน Chrome
3. **เก็บภาพ:** กดเลข `1`–`6` บนคีย์บอร์ด (หรือคลิกปุ่ม) ปุ่มแสดงจำนวนภาพที่มีแล้ว ต้องมีอย่างน้อยชนิดละ 20 ภาพ แนะนำ 100 หลายระยะ หลายมุม หลายแสง
   - **`none`** คือพื้นสนามที่ไม่มีป้าย ต้องเก็บด้วย ไม่งั้น model จะเลือกป้ายสักอันในทุกเฟรม
   - ภาพเก็บใน `dataset/signs/<ชนิด>/` ที่เดียวกับ `05_sign_viewer.py` และ notebook ภาพที่เก็บจากที่ไหนก็ใช้เทรนได้
4. **เทรน:** เลือก epochs (ค่าเริ่มต้น 10) แล้วกด **เริ่มเทรน**
   - ใต้ปุ่มแสดง accuracy ของแต่ละ epoch วัดจากภาพ 20% ที่แยกไว้ไม่ให้ model เห็นตอนเทรน
   - โปรแกรมเก็บเฉพาะ epoch ที่ accuracy ดีที่สุดไว้ที่ `models/sign_resnet18.pth`
   - ระหว่างเทรนภาพกล้องยังเดินอยู่ แต่พักการทายภาพไว้ เพราะ RAM 4 GB ใช้ร่วมกันระหว่าง CPU กับ GPU
   - กด **หยุดเทรน** ได้ตลอด model ที่ดีที่สุดจนถึงตอนนั้นยังอยู่
5. **ทดสอบสด:** ถือป้ายหน้ากล้อง ตัวเลขใหญ่ด้านบนแสดงชื่อป้ายและความมั่นใจ เช่น `STOP 93%`
   - **ความมั่นใจขั้นต่ำ** (ค่าเริ่มต้น 0.7): ทายต่ำกว่าค่านี้จะแสดง `-` เพิ่มค่าถ้าเห็นป้ายผีบ่อย ลดค่าถ้าป้ายจริงไม่ขึ้น
   - ทายผิดที่มุมหรือระยะไหน เก็บภาพมุมนั้นเพิ่มแล้วเทรนใหม่
6. ปิดแล้วเปิดโปรแกรมใหม่ model เดิมจะถูกโหลดให้อัตโนมัติ กด `Ctrl` + `C` ใน Terminal เพื่อหยุด

| ข้อความบนหน้าเว็บ | สาเหตุ |
| :--- | :--- |
| ภาพยังไม่พอ: ... | ชนิดที่ระบุมีภาพไม่ถึง 20 ภาพ |
| ไม่พบไฟล์ models/resnet18-f37072fd.pth | repo บนรถเก่ากว่าตอนที่เพิ่มไฟล์นี้ สั่ง `git pull` |
| เทรนไม่สำเร็จ: CUDA out of memory | ปิดโปรแกรมอื่นที่ใช้ GPU (notebook ที่ค้าง kernel อยู่) แล้วลองใหม่ |
| โหลด model ไม่ได้: No module named 'torch' | รันบนเครื่องที่ไม่มี PyTorch ให้รันบนรถ |

แท็บนี้มีใน `jetbot_app.py` ด้วยในชื่อ **5 ป้าย CNN** โค้ดอยู่ที่ `jetbot_nstru/app/cnn.py` (หน้าเว็บ) และ `jetbot_nstru/cnn.py` (การเทรนและทายด้วย PyTorch)

## Module 6–7 แบบสคริปต์: รันทั้งภารกิจ

`06_mission_runner.py` เปิดแท็บภารกิจในโหมด **ดูอย่างเดียว** กด **Start** แล้วถือรถเดินตามสนาม ดูว่า FSM เปลี่ยน state และอ่านป้ายถูกจังหวะไหม รายการเหตุการณ์จะขึ้นบนหน้าเว็บ พอมั่นใจแล้วเอาติ๊ก **ดูอย่างเดียว** ออก (ทำได้ตอนรถหยุดเท่านั้น) รถจะวิ่งเอง

`07_race_runner.py` ใช้ในวันแข่ง มีแท็บภารกิจ PID และเส้นดำ ให้จูนต่อได้ระหว่างรอบโดยไม่ต้องปิดโปรแกรม

- **ชดเชยแบตเตอรี่**: เร่งความเร็วขึ้นเมื่อแบตอ่อนกว่าตอนบันทึก (สูงสุด 1.25 เท่า) กด **บันทึก** ตอนรถวิ่งได้ดี แรงดันแบตตอนนั้นจะเป็นค่าอ้างอิง
- จบแต่ละรอบ หน้าเว็บแสดงเวลา โบนัสประมาณ และ Net Time ประมาณ (ยังไม่รวม penalty) และเพิ่มหนึ่งแถวใน `race_log.csv` ที่ root ของ repo
- รถหยุดเองเมื่อจบภารกิจ ครบ 90 วินาที หรือมองไม่เห็นเส้นเกิน 2 วินาที

```bash
cd ~/jetbot-mini-bootcamp-nstru
python3 jetbot_app.py            # ใส่ --port 8081 ถ้า 8080 ถูกใช้อยู่
```

### จอแสดงผลสำหรับโปรเจกเตอร์: `/live`

กดลิงก์ **จอแสดงผล ↗** มุมบนของหน้าหลัก หรือเปิด `http://10.42.0.1:8080/live` บนอีกเครื่องที่ต่อโปรเจกเตอร์ จะได้หน้าแบบเดียวกับคลิปสาธิต ภาพกล้องสด จอ OLED จำลองที่แสดงข้อความล่าสุดที่โค้ดสั่ง ตาราง Net Time ที่นับเวลาและโบนัสระหว่างรถวิ่ง และบรรทัดล่างบอกว่า FSM กำลังทำอะไร

- หน้านี้ดูได้อย่างเดียว กด Start / Stop จากหน้าหลักเท่านั้น
- เปิดหน้านี้ค้างไว้กี่จอก็ไม่ทำให้รถวิ่งต่อ ถ้าหน้าหลักปิดหรือหลุด Wi-Fi รถยังหยุดเองเหมือนเดิม และหน้านี้จะขึ้นว่า **หน้าควบคุมปิด รถไม่วิ่ง**  (ยกเว้นรอบที่เริ่มด้วยปุ่ม KEY1 ใน `jetbot_race.py` จะขึ้นว่า **วิ่งด้วยปุ่ม KEY1**)
- โบนัสบนจอเป็นค่าประมาณจากสิ่งที่โค้ดทำ ไม่รวม penalty กรรมการเป็นผู้ตัดสินจริง
- ไม่มีแผนที่สนาม เพราะ JetBot Mini ไม่มี encoder ล้อ จึงไม่รู้ตำแหน่งตัวเองบนสนาม

## `jetbot_race.py`: วันแข่ง เริ่มและหยุดด้วยปุ่ม KEY1

จูนค่าทุกอย่างผ่านหน้าเว็บ แล้วให้รถเริ่มวิ่งจากปุ่ม **KEY1** บนบอร์ดหุ่นยนต์ ไม่ต้องกดจากคอมพิวเตอร์

```bash
cd ~/jetbot-mini-bootcamp-nstru
python3 jetbot_race.py           # ปิด kernel ของ notebook ทุกตัวก่อน
```

1. เปิด `http://10.42.0.1:8080` จูนในแท็บ 2 Trim, 3 เส้นดำ, 4 PID, 5 ป้าย และ cross_time / turn_speed / cooldown ในแท็บแรก แต่ละแท็บมีปุ่มบันทึกลง `my_params.json`
2. กลับมาที่แท็บ **แข่ง (KEY1)** วางรถที่ START แล้วกด KEY1 หนึ่งครั้ง รถเริ่มวิ่งและเริ่มจับเวลาทันที มีเสียง Buzzer และจอ OLED ขึ้น GO
3. กด KEY1 อีกครั้งเพื่อหยุด เวลา โบนัสประมาณ และ Net Time ขึ้นบนหน้าเว็บ และทุกรอบถูกบันทึกต่อท้าย `race_log.csv`

- KEY1 ใช้ได้เฉพาะตอนอยู่แท็บแรก ถ้าไม่ได้เปิดหน้าเว็บเลยก็กด KEY1 ได้ เพราะแท็บแรกถูกเลือกไว้ตั้งแต่เริ่มโปรแกรม
- รอบที่เริ่มด้วย KEY1 ยังวิ่งต่อแม้ Wi-Fi หลุดหรือพับจอคอมพิวเตอร์ ส่วนรอบที่กด Start บนหน้าเว็บจะหยุดเมื่อหน้าเว็บหลุดเหมือนแท็บภารกิจปกติ
- รถหยุดเองเมื่อกด KEY1, กด Stop หรือ Space บนหน้าเว็บ, ปิดหน้าเว็บ, ครบ 90 วินาที หรือไม่เห็นเส้นนานเกิน 2 วินาที
- อย่ากด KEY1 ค้างตอนสั่งรันโปรแกรม โปรแกรมอ่านสถานะปุ่มตอนเริ่มว่าเป็น "ไม่ได้กด"
- ถ้าอ่านปุ่มไม่ได้ (เช่น ไม่มีไลบรารี GPIO) หน้าเว็บจะบอก และยังใช้ปุ่ม Start บนหน้าเว็บได้
- `/live` ใช้กับโปรแกรมนี้ได้เหมือนเดิม

โค้ดอยู่ใน `jetbot_nstru/app/race.py` สืบทอดจากแท็บภารกิจ เพิ่มแค่การอ่านปุ่ม KEY1

อยากเพิ่มความสามารถเอง ให้เขียน class ที่สืบทอด `Panel` แล้วเพิ่มลงใน `PANEL_TYPES` จะได้แท็บใหม่ที่ใช้กล้อง หน้าเว็บ และระบบหยุดรถอัตโนมัติร่วมกับแท็บอื่น ตัวอย่างอยู่ใน docstring ของ `jetbot_app.py` โค้ดของทุกแท็บอยู่ใน `jetbot_nstru/app/`
